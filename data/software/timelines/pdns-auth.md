# PowerDNS Authoritative Server (pdns-auth) DNSSEC timeline

Generated 2026-09-29 from `out/software_repos/pdns.git` (bare clone shared with pdns-rec and dnsdist), `data/software/cve_inventory.json` and the security advisories under `docs/security-advisories/`. Machine-readable twin: `data/software/timelines/pdns-auth.json`.

**Releases:** 196 tags (132 stable), 2002-11-28 .. 2026-08-03. Tags `pdns-2.9*` (pre-split), then `auth-*`. Release date = commit date of `<tag>^{commit}`. Role: authoritative server and online signer; it does not validate, so only signing defaults, NSEC3 handling, CDS/CDNSKEY publication and DNSSEC-related limits are recorded. 330 keyword-filtered changelog entries are in the JSON (unchanged from stage 2).

Changelog files: `pdns/docs/pdns.sgml` (pdns-2.9 .. auth-2.9.22), `pdns/docs/pdns.xml` (auth-3.x), `docs/markdown/changelog.raw.md` (4.0.x), `docs/changelog/{pre-4.0,4.0 .. 5.1}.rst` (read at a later tag, `changelog_source_tag` per release). auth-3.4.10 and auth-3.4.11 have no changelog section anywhere in the clone.

Branching: point releases are cut on `rel/auth-X.Y.x` branches with cherry-picked commits that have different hashes from master. Every fix below was therefore searched per branch and the earliest tag by commit date is reported, with siblings listed. Tags with prefix `rec-`/`dnsdist-` are ignored.

## How to verify a row

```
C=out/software_repos/pdns.git
git -C $C log -1 --format=%cI <tag>^{commit}                       # release date
git -C $C show --format='%H %cI %s' --name-only <commit>            # date, subject, files (must be pdns/ or modules/, not regression-tests/ or docs/)
git -C $C merge-base --is-ancestor <commit> <tag>^{commit} && echo yes   # same relation as: git tag --contains <commit> | grep -x <tag>
git -C $C show <tag>:pdns/common_startup.cc | grep -n 'default-ksk-algorithm\|max-nsec3'   # value at the tag (auth-main.cc from 4.9.0)
git -C $C show <tag>:pdns/pdnsutil.cc | grep -n '1 0 0 -\|1 0 1 ab'
```

`git tag --contains` on this repo takes over two minutes per commit, so memberships were checked per release tag with `merge-base --is-ancestor`; all release tags dated between the commit and 500 days later were scanned in date order, and tags dated before a commit cannot contain it.

Notes:

* The 4.0.0 switch to ECDSA P-256 took four commits in pre-releases (5209ee174 drop default KSK; d113baca3 ZSK -> ecdsa256; b6bd795ce removes the RSA size fallback; 1fe96a070 moves ecdsa256 to the KSK setting). auth-3.4.11 still has `rsasha256`; auth-4.0.0 has `default-ksk-algorithms=ecdsa256` and an empty ZSK list (combined key). Existing keys are never re-keyed.
* Every commit above touches `pdns/` or `modules/`; the `files_touched` list in the JSON shows all files (the 2021 NSEC3 commit 6830fcce2 also edits docs and 5a5d565f0 also edits docs and a regression test, but both change product code in `pdns/pdnsutil.cc` / `pdns/common_startup.cc`).
* At auth-4.5.0 `pdnsutil.cc:106` still declares its own `max-nsec3-iterations` default of "500"; only the server default became 100.
* `add-superfluous-nsec3-for-old-bind` yes->no shipped only on the 3.3.x branch (auth-3.3.2); the option was removed in auth-3.4.0-rc2.

## Gaps

* auth-3.4.10 and auth-3.4.11: no changelog section for these versions exists anywhere in the clone (not in pdns/docs/pdns.xml on rel/auth-3.4.x, not in docs/markdown/changelog.raw.md at auth-4.0.9, not in docs/changelog/pre-4.0.rst at auth-4.1.0..master); changelog_entries left empty.
* news_edits: not determined. Changelog sections for 4.x were recorded on master/branches after each release and were read at a later tag; a per-release comparison of section-at-release-tag vs section-at-latest was attempted for docs/changelog/*.rst but the file mostly does not exist at the release tag (and the run exceeded its time budget), so news_edits is left empty rather than guessed.
* CVE-2008-3337: the actual fix release auth 2.9.21.1 (commit ef29748a9, 2008-08-07) has no tag in the clone; fix_tag auth-2.9.22 (2009-01-25) is assigned by content, and git ancestry disagrees (auth-2.9.22 is a flat-layout tree; first ancestry tag is auth-3.0). Latency +170 d is an upper bound; the real latency was -1 d.
* CVE-2012-0206: NVD names 2.9.22.5, which has no tag in the clone; fix_tag auth-3.0.1 is the earliest tag containing the fix.
* CVE-2019-10203: fix is a schema change (gpgsql notified_serial BIGINT), not C++; "fixed in tag" means the shipped schema file.
